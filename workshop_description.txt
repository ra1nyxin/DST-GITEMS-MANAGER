DST-GITEMS-MANAGER

Server-side dropped item manager focused on practical shard cleanup and retrieval.

中文

当前功能：
- 房间内所有玩家都可以按住已配置修饰键、再按已配置快捷键打开 `GIM`，默认是 `V+N`。
- 面板打开时按 `Esc` 也可以关闭，可在模组配置里关掉这个行为。
- `GIM` 只在面板打开时才开始扫描当前玩家所在 shard 里的地面掉落物。
- 扫描过程中再次按已配置快捷键关闭面板，会立刻中断当前扫描。
- 列表会把当前 shard 的所有地面掉落物按总数量从高到低排序。
- 每个物品行都有 `Take` 和 `CTake` 两个按钮：`Take` 正常往玩家物品栏和背包里拿；`CTake` 按地上现存数量复制一份塞进背包，地面原件不会消失。
- 背包空间不够时，只会拿刚好塞得进去的那部分，不会溢出。
- 对大堆叠环境按服务器当前真实库存规则结算，兼容常见 `99 stack` 类模组。

补充说明：
- 这里只统计当前玩家所在的 shard，主世界和洞穴分别独立看。
- 统计按真实数量算，不是只看地上有几组实体。
- 当前 UI 刻意保持朴素，不带额外贴图资源，重点是够用和稳定。
- 这是服务端模组，不是 clientOnly；客户端也需要安装。
- 当前版本支持在游戏内模组配置里修改修饰键（默认 `V`）、主键（默认 `N`）和 `Esc` 关闭行为（默认开启）。
- 已记录：dedicated server 不该去加载本地 HUD widget，UI 注入逻辑必须先做 `not TheNet:IsDedicated()` 这类隔离。
- 已记录：被 `require` 的子脚本在 strict 环境里不要顶层裸用 `GLOBAL`；更稳的写法是 `local _G = _G`，否则可能直接把 shard 启动打崩。
- 已记录：不要默认认为原生 Lua 全局在 mod 环境里都还在；这次 `rawget(_G, "TheNet")` 就直接报了 `rawget` 是 nil，所以这里回退成了更稳的 `_G.TheNet`。
- 已记录：原版 `ScrollableList` 走 `static_widgets` 模式时不会自动把行控件挂进显示树；如果忘了手动 `AddChild`，就会出现统计有数但列表看起来全空的假象。
- 已记录：`images/ui.xml` 里的 `blank.tex` 更适合透明占位，不适合拿来做真正可见的背景底；要做实色底板，`images/global.xml` 里的 `square.tex` 更稳。
- 已记录：原版滚动条和默认按钮在这种实时更新列表里交互边界不太稳；当前版本已经换成自绘长方形按钮和固定行翻页，尽量减少 hover/拖动时的崩溃面。
- 已记录：HUD 布局里不要把翻页按钮、页码、关闭提示和列表内容混在同一块自由摆放；拆成 header/list/footer 三段再做固定列对齐会稳很多。
- 已记录：DST 这类 HUD widget 不是天然裁剪容器，列表行如果总高度超出真正的 viewport，就会直接视觉上盖到状态文字、列头和 footer；所以行数、行高、间距要先把几何算对，再谈细节排版。
- 已记录：`Text:SetPosition(x, y)` 的 `x` 是区域中心，`SetRegionSize(w, h)` 之后这一列的实际边界是 `x ± w/2`；按左边缘算会整列左移，右边的 `Count` 数字会被按钮压住看不见。
- 入口在 `modmain.lua`，先 `modimport("scripts/gim.lua")`，再用 `AddClassPostConstruct("screens/playerhud", ...)` 把客户端 HUD 面板挂进去。
- 按键切换是包 `PlayerHUD:OnRawKey`，按下主键时用 `TheInput:IsKeyDown(修饰键)` 判定组合，抬起主键才真正开关，默认 `V+N`。
- `Esc` 关闭是包 `PlayerHUD:OnControl` 并吃掉 `CONTROL_PAUSE` / `CONTROL_CANCEL`，不走 `OnRawKey`，否则会顺带弹出暂停菜单。
- 客户端到服务端的请求入口是 `request_scan`、`cancel_scan`、`request_pickup`、`request_copy` 四个 `ModRPC`。
- 服务端回包走 `scan_begin`、`scan_chunk`、`scan_complete`、`pickup_result`、`copy_result` 五个 `ClientModRPC`。
- 分帧扫描靠 `player:DoTaskInTime(0, ...)` 跑 `Ents`，拾取容量判断靠 `inventory:CanAcceptCount` + `inventory:GiveItem`，兼容大堆叠也是跟着这套真实库存接口走。
- `CTake` 用 `SpawnPrefab` 造复制品，按 `stackable.maxsize` 分段、`CanAcceptCount` 算容量、`GiveItem` 入库，数量由服务端重新数地上原件得出，不信任客户端数字。
- 行宽 804 的列分配固定为 `Item 260 / Prefab 190 / Count 84 / Take 88 / CTake 88`，间隔 `10 / 10 / 14 / 10`，左右各 25 内边距，列头、行文本和按钮共用同一套中心点。
- 玩家扫描态挂在 `player._gim_scan_open / _gim_scan_serial / _gim_scan_state / _gim_scan_task`，回看取消和重扫问题先查这里。

English

Current features:
- Every player in the room holds the configured modifier key and presses the toggle key to open `GIM`. The default is `V+N`.
- `Esc` also closes the panel while it is open; this can be turned off in the mod config.
- `GIM` only starts scanning when the panel is opened.
- The scan is limited to the current shard the player is in.
- Pressing the configured hotkey again during scanning closes the panel and cancels the active scan immediately.
- The list is sorted by total dropped item count from highest to lowest.
- Every row has `Take` and `CTake`: `Take` moves that prefab into the player's inventory and backpack space, `CTake` duplicates the same amount into the inventory while the ground stacks stay.
- If inventory space is limited, pickup and copy only take the amount that actually fits.
- Larger-stack environments are handled through the live server inventory rules, including common `99 stack` style setups.

Notes:
- Only the current shard is counted, so overworld and caves stay separate.
- Counts use real stack size rather than just ground entity count.
- The UI is intentionally plain and asset-free in this version.
- This is a server-side mod, not a client-only one, so clients also need the mod installed.
- `GIM` config entries cover the modifier key (default `V`), the toggle key (default `N`), and whether `Esc` closes the panel (default on).
- Recorded pitfall: dedicated server shards should not load local HUD widget modules, so the UI hook is guarded on non-dedicated environments only.
- Recorded pitfall: under DST strict mode, required helper/widget files should avoid top-level `GLOBAL` reads and prefer `local _G = _G`.
- Recorded pitfall: do not assume every stock Lua global is available inside the mod environment; this mod hit `rawget` being nil during startup, so direct `_G.TheNet` access is the safer path here.
- Recorded pitfall: vanilla `ScrollableList` does not automatically parent `static_widgets`, so forgetting to `AddChild` the row widgets can leave you with valid scan totals and an apparently empty list.
- Recorded pitfall: `images/ui.xml` `blank.tex` is better treated as a transparent placeholder than a real visible panel fill, so solid backgrounds should use `images/global.xml` `square.tex`.
- Recorded pitfall: stock scrollbars and default button skins can be brittle inside live-updating custom lists, so this version switches to drawn rectangular buttons and fixed-row paging for a safer interaction path.
- Recorded pitfall: do not let paging controls, page text, close hints, and row content share one loose layout block; a dedicated header/list/footer split with fixed columns is much more stable.
- Recorded pitfall: DST HUD widgets are not automatic clipping containers. If the total row stack exceeds the actual viewport, rows will visibly cover the status line, column labels, and footer, so row count, row height, and spacing have to fit the geometry first.
- Recorded pitfall: `Text:SetPosition(x, y)` centers the region on `x`; after `SetRegionSize(w, h)` the column spans `x - w/2` to `x + w/2`. Treating `x` as the left edge shifts the column left and lets buttons cover the `Count` values.
- Recorded pitfall: do not hook this hotkey via `TheInput:AddKeyDownHandler`; that handler ignores the active screen and also fires while chat or the console is open. `PlayerHUD:OnRawKey` is the in-game HUD layer.
- Recorded pitfall: `Esc` arrives as `CONTROL_PAUSE` (and sometimes `CONTROL_CANCEL`), so `PlayerHUD:OnControl` has to be wrapped; `OnRawKey` alone cannot prevent the pause menu.
- Recorded pitfall: `inventory:GiveItem` drops items on the ground when it cannot fit, so copy paths must `CanAcceptCount` first and `Remove()` the freshly spawned entity on failure.
- Bootstrap path: `modmain.lua` -> `modimport("scripts/gim.lua")`.
- HUD injection: `AddClassPostConstruct("screens/playerhud", ...)`.
- Toggle key hook: wrapped `PlayerHUD:OnRawKey`; combo state comes from `TheInput:IsKeyDown(modifier)` on key down and the panel is toggled on key up, default `V+N`.
- Client to server RPCs: `request_scan`, `cancel_scan`, `request_pickup`, `request_copy`.
- Server to client RPCs: `scan_begin`, `scan_chunk`, `scan_complete`, `pickup_result`, `copy_result`.
- Scan slicing: `player:DoTaskInTime(0, ...)` over `Ents` in batches.
- Capacity check path: `inventory:CanAcceptCount(...)` -> optional `stackable:Get(...)` -> `inventory:GiveItem(...)`.
- CTake path: `SpawnPrefab(...)` -> clamp to `stackable.maxsize` -> `CanAcceptCount` -> `GiveItem`; the count is recounted on the server from ground items.
- Row geometry inside the 804-wide row background: `Item 260 / Prefab 190 / Count 84 / Take 88 / CTake 88` with `10 / 10 / 14 / 10` gaps and 25 padding per side; headers, row text, and buttons share the same region centers.
- Player scan state fields: `_gim_scan_open`, `_gim_scan_serial`, `_gim_scan_state`, `_gim_scan_task`.
